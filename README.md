# retter.wang — personal homepage

English | [简体中文](README.zh-CN.md)

Source of my personal homepage, served at **[retter.wang](https://retter.wang)** via GitHub Pages.

## What's in it

A single self-contained page — no build step, no framework, no external JavaScript. It covers:

- **About** — a short bilingual introduction
- **Projects** — the things I build and maintain, including
  [Saudade](https://apps.apple.com/cn/app/saudade/id6827383744) for iOS, the
  [CAMCOP](https://camera.abetterplace2.live) camera comparison tool (1,144 cameras, five views,
  plus a WeChat Mini Program) and the `abetterplace2.live` site cluster
- **Experience** — a condensed work history

The page ships in eight languages — Simplified Chinese, Traditional Chinese, English, Japanese,
Korean, French, Spanish and German — the same set used on the Saudade site. Each view is
single-language: the Chinese pages carry Chinese only, with no English translation lines under the
content (the standalone `contact` label and the footer's "Last updated" stay in English by design).
The switcher sits in the top-right corner, the choice is remembered in `localStorage`, and a URL
such as `?lang=ja` opens a specific language directly. The Chinese copy is written into the markup
itself, so the page still reads correctly with JavaScript disabled.

## Deployment

Commits to `main` are published automatically by GitHub Pages — there is no build or CI step.

```bash
git add .
git commit -m "content: ..."
git push
```

DNS for `retter.wang` points at GitHub Pages, with the custom domain recorded in `CNAME`.
TLS is provisioned by GitHub.

## Blog (`/blog/`)

A self-contained static blog generator lives in `blog/`:

```
blog/
├── build.py        # scans posts/*.md → index.html, feed.xml, posts.json
├── posts/          # Markdown sources with YAML front matter
├── index.html      # generated post list
└── feed.xml        # generated RSS 2.0
```

Rebuild after editing posts:

```bash
cd blog && python build.py    # requires: markdown, pyyaml
```

### Content provenance labels (required)

Every post must declare its origin in front matter via `author_type`. The builder
renders the matching badge on both the post page and the list page.

| `author_type` | Badge | Meaning |
|---|---|---|
| `ai` | **AIGC** (pink) | Generated by AI, then reviewed and fact-checked by a human |
| `human` | **HMGC · 人工创作** | Written entirely by a human |

For `ai` posts the builder additionally emits:

- an explicit disclosure block at the top of the article body,
- `<meta name="aigc" content="ai-generated">` in `<head>` (machine-readable).

This satisfies the explicit and implicit labeling requirements of China's
*Measures for Labeling Artificial Intelligence-Generated Synthetic Content*.
The field defaults to `human` when omitted — always set it explicitly so nothing
is published unlabeled.
